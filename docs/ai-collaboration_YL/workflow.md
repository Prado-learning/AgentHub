# Workflow 协作流程

## 1. 接收任务

- 先读需求，确认目标、边界、优先级和风险。
- 如果信息不足，先补齐上下文，再动手。

## 2. 理解现状

- 先看仓库结构、相关代码、历史记录和已有规范。
- 找到本次任务真正影响的模块，不扩大范围。

## 3. 拆任务

- 把任务拆成可执行的小步。
- 区分必须做、最好做、暂缓做三类。

## 4. 执行

- 按最小改动原则实现。
- 能复用现有 pattern 就复用，不额外发明结构。
- 对文档任务，优先补结构和链接；对代码任务，优先补测试和边界。

## 5. 验证

- 跑相关测试、构建或最小可复现检查。
- 记录失败原因和剩余风险，不跳过验证就宣布完成。

## 6. 总结

- 说明改了什么、为什么改、验证了什么。
- 给出仓库产物地址和飞书文档入口。

## 7. 归档

- 把可复用规则沉淀进 `spec.md`、`rules.md`、`skills/`。
- 把阶段性总结放进 `timeline.md`，方便后续继续迭代。
