## 一、项目简介

**AgentHub** 是一个基于 **agentscope** 的多智能体协作工作台（IM 式「天工作天」聊天台）。
它通过对话的方式，把多个具备不同分工的 Agent 组织起来协同完成任务，并把过程产物（代码、预览、Diff、部署、Workflow 等）沉淀到右侧产物面板中。

**核心 Agent 分工：**

| Agent | 职责 |
| --- | --- |
| Orchestrator | 规划与分派，按 UI / 文件 / 图片 / 预览 / 部署等意图拆步骤 |
| Codex | 代码生成与二次编辑 |
| UI Builder | 界面与前端产物 |
| Code Reviewer | 审查与质量把关 |

经过协作迭代，AgentHub 已从「基础多智能体聊天工作台」扩展为具备以下能力的协作平台：
IM 式会话管理、单聊 / 群聊协作、`@Agent` / `@Tool` 分派、文件与图片上传分析、代码 / 预览 / Diff / 部署等产物管理、版本恢复与上下文连续、Workflow 产物创建编辑运行、右侧产物面板与协作结果联动展示。

## 二、技术结构与关键入口

**前端（Vite / React）：** `app/web/src`，主要入口 `App.tsx`、`styles.css`。

**后端（Python 服务）：**

| 模块 | 职责 |
| --- | --- |
| `rule_planner.py` | 单聊 / 群聊 / `@Agent` 解析、规则分派 |
| `coordinator.py` | 多 Agent 执行（依赖步骤、并行、失败 fallback、事件记录、聚合） |
| `send_message.py` | 上下文连续：聊天历史、Pin、长上下文 summary、智能记忆 |
| `attachment_service.py` | 文件 / 图片上传、压缩、文本提取、附件下载 |
| `agent_service.py` / `agent_creation_service.py` | 用户自建 Agent 的列表与对话式创建流程 |
| `artifact_service.py` | code / preview / diff / deployment / document_preview 等产物持久化与版本记录 |
| `preview.py` | 网页预览（iframe，HTML / preview_url） |
| `diff_service.py` | 结构化 Diff 展示、应用、备份、回滚 |
| `deploy.py` | 一键本地静态部署，生成 `/deployments/.../index.html` |
| `document_preview.py` | 文档 / PPT 卡片与链接预览 |
| `conflict_resolver.py` | 多产物冲突检测，生成 conflict artifact |
| `agents.yaml` / `agents.py` | 内置 Agent 配置、头像、能力标签、工具列表 |

## 四、协作过程记录

### 会话一：项目摸底与课题对齐

确认 AgentHub 当前已实现哪些功能、哪些尚未实现，并把项目现状与课题要求逐项对照。

- **用户的指导方式：** 先阅读整个项目和需求，不直接改代码；只输出功能完成情况；关注多 Agent 协作、IM 聊天、上下文、产物预览、Diff、部署等核心能力；最后整理成清单。
- **我的协作方式：** 先读项目结构、README、前后端入口与主要服务；把代码能力映射到课题要求；输出「已实现 / 部分实现 / 未实现」清单；补充各模块所在文件便于后续定位。
- **价值：** 把系统能力边界摸清楚，为后续迭代建立事实基础，避免一开始就盲目加功能。

### 会话二：交互与 UI 细节优化

对产品交互做细节优化，强调「看起来像一个完整的协作工作台」，而不是只有功能堆叠。

- **用户的指导方式：** 要求最小化改动；不动文件结构与重要框架；对已有交互提细节调整（去冗余文案、调整模式切换、优化消息操作按钮、置顶会话加图标、回收站缩成左下角小图标、Markdown 渲染为真正格式）。
- **我的协作方式：** 先判断每个请求是否属于必要优化；只对明确确认的交互做最小改动；保持整体视觉风格一致；修改后做前端构建验证。
- **价值：** 把系统从「能用」推进到「可展示、像产品」，尤其适合答辩和录屏时体现完成度。

### 会话三：问题排查与使用流程支持

排查系统问题，并指导 Git / VSCode 基础流程，属于协作中「帮你打通工作流」的部分。

- **用户的指导方式：** 模型调用失败时先排查原因，不改代码；一步步指导把代码提交到 GitHub；队友拉新代码后帮助判断是否覆盖本地；检查 HTML 为什么不能预览；要求解释原因而非给「结论式操作」。
- **我的协作方式：** 根据终端输出、界面状态、Git 状态判断问题类型；讲清 `fetch / pull / fast-forward / push`，避免误操作；解释「拉取远程代码」与「覆盖本地改动」的区别；对预览问题做产物链路分析（问题在产物类型没落到正确的预览路径，而非 HTML 文件本身损坏）。
- **价值：** 帮助建立对项目和开发流程的稳定理解，让后续录屏、排查、答辩更有底气。

### 会话四：Workflow 与产物能力增强

在前述基础上扩展 Workflow 产物能力（创建、编辑、运行）与右侧产物面板联动，进一步把协作结果产品化。

- **用户的指导方式：** 在不破坏现有架构的前提下增强 Workflow / artifact 能力，接入现有 orchestrator / artifact 体系。
- **我的协作方式：** 复用现有 artifact 与 workflow 流程；新增 `workflow_builder_tool` / `workflow_runner_tool` 等能力时接到现有体系；保证产物面板与协作结果联动展示。
- **价值：** 让 AgentHub 从聊天台进一步成为「可创建、可运行、可展示产物」的协作平台。

## 五、可复用的 AI 协作方法

本次协作过程本身也形成了一套可复用的方法（与《AI 协作规范》对应）：

- 先对齐目标，再动手实现。
- 先分析项目现状，再决定改动范围。
- 先做最小可用版本，再逐步增强。
- 遇到问题先排查，再修改。
- 所有改动都保持对现有架构的尊重。
